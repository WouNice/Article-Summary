# 代码发布方式总结

代码开发中的发布方式关乎系统稳定性和用户体验，不同策略适合不同风险容忍度和架构复杂度。以下总结几种主流发布模式，从基础到进阶依次说明：

## 滚动部署
**原理**：逐个或分批替换旧版本实例，新版本逐步上线，旧版本逐步下线，整个过程不停机。

**特点**：

- 无需额外资源，直接利用现有集群更新。
- 更新期间新旧版本会短暂共存，需确保接口向前/向后兼容。
- 若新版本有问题，影响范围逐渐扩大，回滚需反向操作耗时较长。

**适用**：中小型服务、对资源敏感、无严格零停机要求的场景。

## 蓝绿部署
**原理**：准备两套完全对等的生产环境——蓝环境（当前线上）和绿环境（新版本）。发布时先将流量切换到绿环境，验证无误后保留绿环境，蓝环境转为备用或销毁。

**特点**：

- **瞬时切换**，几乎无感知停机。
- **回滚极快**：切回蓝环境即可，秒级恢复。
- 需要**双倍资源**（除非用云资源按需创建）。
- 数据库迁移需特别处理，通常采用兼容升级或双写方案。

**适用**：核心业务、对可用性要求苛刻、允许资源冗余的场景。

## 金丝雀发布
**原理**：先让一小部分用户或流量进入新版本（金丝雀），监控各项指标和错误率，逐步扩大流量比例，直至全量替换旧版本。

**特点**：
- 风险**可控**，用真实流量验证新版本，最小化影响面。
- 对**监控和流量调度**能力要求高（需配合网关、服务网格）。
- 可与滚动部署结合（先金丝雀一小批，再滚动全量）。

**适用**：高流量互联网应用、需要灰度验证新功能的场景。

## 不可变部署
**原理**：任何变更（包括配置、代码）都通过**全新构建**镜像或实例来交付，绝不修改已运行的服务器。旧实例直接被新实例**替换**，而非在原有实例上更新。

**关键点**：

- 服务器实例一旦启动，**禁止任何登录修改**（配置通过环境变量或配置中心注入）。
- 发布即**销毁旧容器/虚拟机，启动新版本**，类似于滚动但强调不可变性。
- 与容器化（Docker/K8s）理念天然契合。

**优点**：

- **一致性**极强，避免“配置漂移”和“雪花服务器”。
- **回滚即部署旧镜像**，状态明确。
- 简化运维，排错时可确定环境与构建一致。

**对比蓝绿**：不可变部署强调**实例本身的不可更改性**，蓝绿是**流量切换的两套环境**。实践中蓝绿环境里的实例也常采用不可变镜像。

## A/B 测试
**原理**：同时运行两个或多个版本，根据用户属性（如ID、地区）将流量定向到不同版本，用以**对比业务效果**（如转化率、留存），而非单纯验证技术稳定性。

**与金丝雀区别**：
- 金丝雀关注**系统健康度**（错误率、延迟），目标是安全上线。
- A/B测试关注**用户行为数据**，目标是产品决策。

**技术实现**：依赖分流网关、Feature Toggle 或客户端实验 SDK。

## 影子测试
**原理**：将生产流量**复制一份**发送到新版本服务，但**新版本的响应不返回给真实用户**。通过对比新旧版本的处理结果和性能，评估新版本正确性。

**特点**：
- 对用户**零影响**，可压力测试真实流量。
- 实现复杂，需流量复制和结果对比基础设施。
- 常用于重构核心模块或更换数据存储。

## 功能开关发布
**原理**：代码中预埋开关，新功能默认关闭。上线后通过配置中心动态开启特定用户群或比例的功能。

**优势**：
- **部署与发布分离**：代码提前合并上线，业务发布时机由开关控制。
- 支持**紧急关停**新功能而无需重新部署。

**常与金丝雀/滚动结合**：先部署含开关的代码，再逐步打开开关。

## 总结对比表

| 发布方式   | 停机时间 | 资源成本       | 回滚速度 | 风险控制         | 典型场景           |
| ---------- | -------- | -------------- | -------- | ---------------- | ------------------ |
| 滚动部署   | 无       | 低             | 慢       | 中               | 一般Web服务        |
| 蓝绿部署   | 几乎无   | 高（双倍）     | 极快     | 高（可预验证）   | 金融、支付核心系统 |
| 金丝雀发布 | 无       | 中             | 快       | 高（逐步）       | 高并发互联网应用   |
| 不可变部署 | 无       | 中             | 快       | 高（一致性）     | 容器化、云原生环境 |
| A/B 测试   | 无       | 中             | 无关     | 产品决策导向     | 运营活动、UI优化   |
| 影子测试   | 无       | 中（额外实例） | 无关     | 极高（离线验证） | 重构、数据库迁移   |

实践中，这些方式常组合使用。例如：**不可变镜像 + 蓝绿环境**保证基础一致性；**金丝雀发布 + 功能开关**实现精细流量控制和快速熔断。选择方案时需权衡团队运维能力、基础设施支持度与业务容忍度。
