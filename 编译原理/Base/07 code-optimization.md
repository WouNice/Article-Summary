# 第7章：代码优化——让程序跑得更快

**用一句话说清楚**：优化就是在**不改程序结果**的前提下，让生成的代码占更少的内存、跑得更快。不是你写 `a = b + c; d = b + c` 编译器就傻傻算两遍——它会发现「这两件事一样」，帮你省掉一次。

## 优化全集（按阶段分类）

优化不只在一个阶段做，而是贯穿编译全过程：

| 阶段 | 优化名称 | 通俗解释 | 效果 |
|------|---------|---------|------|
| **AST 层面** | 常量折叠 | `3 + 5 * 2` 直接算成 `13` | 减少运行时计算 |
| **AST 层面** | 代数简化 | `x * 0 → 0`，`x + 0 → x` | 减少/消除无用运算 |
| **TAC/IR 层面** | 死代码消除 | 删掉 `a = 42; // a 后面再也没用过` | 减少代码量 |
| **TAC/IR 层面** | 常量传播 | `x = 5; y = x + 2 → y = 7` | 把运行时计算变成编译时计算 |
| **TAC/IR 层面** | 公共子表达式消除 | `a = b+c; d = b+c → a = b+c; d = a` | 减少重复计算 |
| **TAC/IR 层面** | 循环不变量外提 | 把循环内不变的计算提到循环外 | 显著减少循环内开销 |
| **TAC/IR 层面** | 循环展开 | `for(i=0;i<100;i+=2){a[i]...a[i+1]...}` | 减少分支次数 |
| **寄存器分配** | 寄存器着色 | 最常用的变量放进最快的寄存器 | 减少内存访问 |
| **指令调度** | 指令重排 | 把 CPU 能并行执行的指令排在一起 | 利用 CPU 流水线 |

## 初学者必须掌握的三种优化

### 优化①：常量传播与折叠

编译器看到常量就当场算出结果，不用等运行时：

```text
源代码：
    x = 5
    y = x + 3
    z = y * 2

优化后（常量传播 + 折叠）：
    x = 5
    y = 8       ← 5+3 已算好
    z = 16      ← 8*2 已算好
```

实现思路：
```c
// 优化器遍历 TAC，遇到常量就传播
if (tac->kind == TAC_ASSIGN) {
    int val = is_constant(tac->arg1);
    if (val != NOT_CONSTANT) {
        propagate_constant(tac->result, val);  // 记录 x=5
    }
}
// 后续看到 y = x + 3 → 查表 x=5 → y = 5+3 → y = 8
```

### 优化②：死代码消除

删掉那些"写了但没人用"的代码：

```text
源代码：
    a = 42            ← 写了但下面没人用 a，可以删掉
    b = 10
    c = b + 5         ← b 还在用，不能删
    return c

优化后：
    b = 10
    c = b + 5
    return c
```

### 优化③：公共子表达式消除

发现两次计算一样的东西，合并成一次：

```text
源代码：
    t1 = a + b
    x = t1
    t2 = a + b        ← 跟 t1 一模一样！
    y = t2

优化后：
    t1 = a + b
    x = t1
    y = t1            ← 重用 t1，省掉一次加法
```

## 机器无关优化 vs 机器相关优化

| | **机器无关** | **机器相关** |
|--|------------|------------|
| 作用层 | IR/TAC 层面 | 指令选择、寄存器分配 |
| 特点 | 跟 CPU 没关系，放之四海皆准 | 为特定 CPU "量身定制" |
| 典型 | 常量传播、死代码消除、循环优化 | 寄存器着色、指令调度 |

## 函数内联：用空间换时间

```c
// 源代码
int square(int x) { return x * x; }
int main() {
    int a = square(5);
    return square(a + 1);
}

// 内联后 — 不再有函数调用开销
int main() {
    int a = 5 * 5;          // square(5) 展开
    int tmp = a + 1;
    return tmp * tmp;        // square(a+1) 展开
}
```

**效果**：去掉函数调用开销（压栈、跳转、返回），但代码体积增大。这是最典型的"用空间换时间"优化。

## 寄存器分配：把最常用的放最近

CPU 寄存器（几十个）比内存（几 GB）快数十倍。编译器需要决定哪些变量"住进"寄存器：

```text
优化前（变量都在内存）：
    movl x, %eax          ← 从内存读
    addl y, %eax
    movl %eax, sum        ← 写回内存

优化后（变量在寄存器）：
    # 编译器决定 x, y, sum 都放在寄存器
    # 整个计算不需要访问内存
```

常用的分配算法是**图着色**——把变量当"结点"，同时期活跃的变量之间连"冲突边"，然后给它们分配不同颜色的寄存器。

## 优化级别：选择你的"激进程度"

| 级别 | 标志 | 做了什么 | 编译时间 |
|------|------|---------|---------|
| **O0** | 无优化 | 逐字翻译，不改动 | 最快 |
| **O1** | 基本优化 | 常量折叠、死代码消除等"安全的" | 稍慢 |
| **O2** | 标准优化 | 除 O1 外增加循环优化和指令调度 | 较慢 |
| **O3** | 激进优化 | 函数内联、循环展开、向量化 | 最慢 |
| **Os** | 体积优化 | 优先减小代码体积，而非速度 | 较慢 |

> ⚠️ **一个反直觉的事实**：`-O3` 不一定比 `-O2` 快！有时函数内联太多会让代码膨胀，导致 CPU 的指令缓存（i-cache）失效，反而变慢。**具体项目需要具体评测。**

## 📝 本章小结

| 概念 | 一句话理解 |
|------|-----------|
| **常量传播** | 编译器替你把常量计算提前做好 |
| **死代码消除** | 删掉写了但没人用的代码 |
| **公共子表达式消除** | 重复计算只算一次，后面直接用结果 |
| **函数内联** | 用函数体替换函数调用，省开销但增大代码 |
| **寄存器分配** | 把热门变量放进最快的存储（寄存器） |
| **优化级别** | O0-O3，从"不优化"到"大刀阔斧改" |
