# 原子操作

## Linux中原子操作怎么实现的？

基于底层硬件指令（以 x86 为例）：

原子整数操作：Linux 内核提供了原子整数操作的接口，如atomic_t类型和相关函数（atomic_read、atomic_set、atomic_add等）。这些操作在底层利用了 x86 处理器的指令，如lock指令前缀与其他算术指令结合。以atomic_add函数为例，当执行atomic_add对一个atomic_t类型的变量v加一个值i时：

编译器会将atomic_add函数调用转换为内联汇编或者调用内核中对应的汇编代码片段。在 x86 架构下，会使用带有lock指令前缀的加法指令（如lock add）。lock指令前缀保证了该指令在多处理器环境下的原子性，它会锁定系统总线或者使用缓存一致性协议来防止其他处理器在这个指令执行期间访问相同的内存位置。

指令首先读取v的值，然后加上i，最后将结果写回v的内存位置，整个过程是一个不可分割的原子操作。

原子位操作：对于原子位操作（如设置、清除、测试位等），Linux 同样利用了处理器的特定指令。例如，在 x86 中，可以使用bts（位测试并设置）、btr（位测试并清除）等指令。

以set_bit函数为例，用于设置一个位：类似于原子整数操作，函数调用会转换为内联汇编或调用对应的汇编代码。使用适当的位操作指令，并且加上lock指令前缀（如果需要）来保证原子性。指令会定位到目标内存位置对应的字节，然后对指定的位进行设置操作，确保在多处理器环境下没有其他处理器同时修改该位。

内存屏障（Memory Barrier）的配合使用：在 Linux 原子操作中，还经常配合内存屏障来保证内存操作的顺序和一致性。内存屏障是一种硬件或软件机制，用于控制处理器对内存操作的顺序。

例如，smp_mb（在 SMP - 对称多处理器系统下的内存屏障）函数。当执行原子操作后可能需要使用内存屏障来确保其他处理器能够看到该原子操作的结果。假设一个处理器执行了一个原子写操作（如更新了一个共享变量），在没有内存屏障的情况下，其他处理器可能会因为缓存一致性等问题而延迟看到这个更新。通过插入适当的内存屏障（如write memory barrier），可以保证在屏障之前的内存写操作（包括原子写操作）对屏障之后的操作（包括其他处理器的读操作）是可见的，从而保证了内存操作的顺序一致性。
