# RCU原理

RCU（Read-Copy-Update）是Linux内核中一种高效的同步机制，专为**读多写少**的场景设计，通过**无锁读**和**延迟更新**实现高并发性能。其核心原理可分为以下部分：

## 核心思想

**读-拷贝-更新（RCU）**

-   读操作：直接访问共享数据，无需加锁或原子指令，几乎零开销。
-   写操作：分三步
    -   **Read**：创建数据的副本；
    -   **Copy**：在副本上修改；
    -   Update：通过原子操作替换旧指针为新副本。
-   延迟回收：旧数据需等待所有读操作完成后（宽限期结束）才释放。

**宽限期（Grace Period）**

-   定义：从写操作更新指针到所有读者退出临界区的时间段。
-   判定条件：所有CPU至少经历一次静止态（Quiescent State）（如上下文切换、用户态执行）。
-   实现：内核通过per-CPU状态跟踪CPU是否进入静止态。

## 关键技术实现

**读者端**

-   使用rcu_read_lock()和rcu_read_unlock()标记临界区，本质是禁用内核抢占，确保读者执行期间不切换线程。
-   通过rcu_dereference()安全获取指针，避免编译器或CPU乱序执行。

**写者端**

-   同步模式：synchronize_rcu()阻塞等待宽限期结束，适合非实时场景。
-   异步模式：call_rcu()注册回调函数，宽限期结束后自动释放旧数据，适合中断上下文。
-   指针发布：rcu_assign_pointer()更新指针并插入内存屏障，确保新数据对其他CPU可见。

**内存屏障与原子操作**

-   RCU依赖内存屏障（如smp_mb()）保证数据更新的顺序性，避免读者看到中间状态。
-   Alpha架构需特殊处理，因其弱内存模型可能导致乱序问题。

## 优势与适用场景

**优势**

-   无锁读：读者无竞争，性能接近无同步状态。
-   无死锁/优先级反转：读者无需与写者交互。
-   高扩展性：多核环境下性能随CPU数量线性增长。

**适用场景**

-   文件系统：目录查找（高频读，低频写）。
-   网络协议栈：路由表查询。
-   内核数据结构：进程表、inode表等。

**限制**

-   仅保护动态分配的指针结构，静态数据不适用。
-   读者临界区不可睡眠或调用可能调度的函数。
-   写者开销大，需额外锁（如自旋锁）同步多写者。

## 与其他锁机制对比

| 机制       | 读者开销         | 写者开销       | 适用场景               |
| ---------- | ---------------- | -------------- | ---------------------- |
| **RCU**    | 近乎零           | 高（延迟回收） | 读多写少，实时性要求高 |
| **读写锁** | 中等（原子操作） | 高（阻塞）     | 读写均衡，需强一致性   |
| **自旋锁** | 高（忙等待）     | 高（忙等待）   | 短临界区，非睡眠场景   |
| **信号量** | 高（上下文切换） | 高（阻塞）     | 长临界区，允许睡眠     |

## 扩展变种

-   可抢占RCU（Preemptible RCU）：允许读者临界区被抢占，提升实时性。
-   SRCU（Sleepable RCU）：支持读者睡眠，牺牲部分性能。
-   用户态RCU（URCU）：将RCU思想扩展到用户空间。

## 总结

RCU通过**空间换时间**（副本复制）和**延迟回收**（宽限期）实现了无锁读与并发更新的平衡，是Linux内核高性能同步的典范。其设计思想（如发布-订阅、多版本控制）也被广泛应用于其他领域（如数据库、分布式系统）。
