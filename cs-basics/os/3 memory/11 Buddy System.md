# Buddy System

Linux的**伙伴系统（Buddy System）**是内核中用于管理物理内存页框的核心算法，旨在高效分配连续内存并减少外部碎片。其核心思想是将物理内存按2的幂次方划分，通过递归拆分与合并机制实现动态管理。以下是其关键要点：

## 核心原理

**内存块划分**

-   以**页（通常4KB）**为最小单位，将空闲内存划分为不同阶（order）的块，每块大小为 $2^{order}$ 页（如1页、2页、4页……最大4MB）。
-   通过free_area[]数组管理11个阶（0~10）的空闲块链表，每个链表存储对应大小的空闲内存块。

**伙伴关系**

-   两个大小相同、物理地址连续的内存块互为“伙伴”，释放时可合并为更大的块。合并条件包括：
    -   大小相同且均为空闲；
    -   地址满足 $\text{address} \mod 2^{order+1} = 0$。

## 工作流程

**内存分配**

-   若申请大小为 $2^n$ 页，优先从free_area[n]链表中分配；若无空闲块，则向上查找更大阶的块并递归拆分。
-   示例：申请3页时，实际分配4页（$2^2$），导致1页内部碎片。

**内存释放**

-   释放的块会检查其伙伴是否空闲，若满足条件则合并为更高阶的块，并递归尝试进一步合并。

## 优势与局限

1.  **优点**
    -   减少外部碎片：通过合并机制回收连续空闲内存。
    -   高效操作：拆分与合并仅需位运算，时间复杂度接近 $O(1)$。
    -   简单结构：仅需维护固定阶的空闲链表。
2.  **缺点**
    -   内部碎片：强制按2的幂次分配可能导致浪费（如申请257KB需分配512KB）。
    -   小对象不适用：需依赖SLAB分配器进一步细分。

## 实际应用

-   场景：主要用于分配大块连续内存（如DMA缓冲区、HugePages）。
-   协同机制：与SLAB分配器分工，前者管理页框，后者处理小对象（如内核结构体）。
-   NUMA支持：在多节点系统中，每个NUMA节点独立维护伙伴系统。

## 调试与监控

通过/proc/buddyinfo查看各阶空闲块数量，分析内存碎片情况。

```v
$ cat /proc/buddyinfo
Node 0, zone      DMA      0      0      0      0      0      0      0      1      0      1      3
Node 0, zone    DMA32      3      4      3      2      3      3      2      4      4      5    662
Node 0, zone   Normal    288    988    380    310    145     68     33     20      7     13     86
```

## 总结

伙伴系统通过**幂次划分**和**伙伴合并**机制，在保证分配效率的同时有效缓解外部碎片问题，是Linux物理内存管理的基石。但其内部碎片问题需结合SLAB等上层分配器优化。
